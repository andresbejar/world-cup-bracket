## Affected Pages/Routes

- `/` — landing / sign-in entry. Test that unauthenticated users see Google sign-in CTA.
- `/predictions` — the main bracket entry UI. Test that authenticated users can view all rounds, submit/edit predictions, and see lock status.
- `/leaderboard` — global ranked list. Test polling refresh, tiebreaker ordering, predicted-vs-real cards.
- `/profile` — username + favorite team. Test that profile edits persist and username validation works.
- `/api/predictions` (POST/PATCH) — server-side write paths. Test lock enforcement, validation errors, auth.
- `/api/cron/poll-results` (Vercel Cron) — hourly polling job. Test that scoring runs idempotently when match status flips to finished.
- `/api/auth/callback` — Supabase Google OAuth callback. Test that a fresh sign-in creates a `users` row.

## Key Interactions to Verify

- **Group-stage prediction entry:** user predicts scores for all 72 group matches, sees their predicted standings update in real-time, sees R32 slots populate based on their predicted group winners/runners-up.
- **Third-place dropdown picks:** user fills the 8 R32 third-place slots from a dropdown of their 12 predicted group third-place teams. Picking the same team twice should be prevented or warned.
- **Knockout round prediction:** user clicks "winner" for each R32 → R16 → QF → SF → Final / 3rd-place match. Their pick cascades to the next round's bracket card.
- **Cascade reactivity:** changing a group-stage score updates the predicted standings, which updates the R32 slot occupants, which updates downstream knockout cards. All in one render cycle — no stale UI.
- **Round lock at deadline:** clock crosses the 4-hour-pre-deadline threshold. Edits succeed up to deadline-minus-1min and fail with a clear error after.
- **Concurrent edits (two tabs):** user edits the same prediction from two tabs. Last write wins. No 500.
- **Sign-in flow:** Google OAuth redirect → callback → `users` row created → username + favorite-team prompt on first login.
- **Match finishes → scoring:** cron job runs, api-football reports a match as finished, all predictions on that match get scored, leaderboard updates within ~30s of next leaderboard poll.
- **Predicted vs. real display:** finished match shows predicted score + real score side-by-side, color-coded green (exact) / yellow (outcome only) / red (wrong).
- **Mobile responsive:** prediction flow on 390px viewport works one-match-at-a-time. Bracket diagram horizontally scrolls.

## Edge Cases

- **Empty predictions:** user signs up but never enters predictions. Leaderboard shows them at 0 pts, ranked by registration time as the final tiebreaker.
- **Partial predictions:** user fills group A but not group B. Standings for B are deterministic-zero. R32 cards for groups they haven't predicted show empty slots.
- **Tiebreaker chain at every step:** group standings tie at points → GD → GS → H2H pts → H2H GD → alphabetical fallback (with UI flag warning user).
- **Knockout score that went to penalties:** real match was 1-1 in regulation, decided 4-3 on penalties. Canonical score = 1-1 (90+ET only). User who predicted "1-1" gets 3 pts; user who predicted "Argentina wins" gets 1 pt for outcome.
- **Withdrawn team / cancelled match:** match status never flips to `finished`. All predictions on that match resolve to 0 pts (treat as not-finished). No partial points.
- **Unauthenticated POST to /api/predictions:** returns 401, no row written.
- **Editing another user's prediction (forged user_id):** RLS rejects, returns 403.
- **Editing after lock:** server-side check rejects, returns 403 with clear message.
- **Knockout outcome prediction = "tie":** validation rejects at submit (knockouts must pick a winner).
- **Score out of sane range (99-99):** validation rejects.
- **Cron job runs twice in same window (Vercel retry):** scoring is idempotent — match scored once, no double-counting.
- **api-football returns 500 / timeout:** cron logs and exits 0, does not crash. Manual fallback via Supabase studio is documented.
- **Two third-place dropdowns picked the same team:** UI prevents or shows warning before submit.
- **Third-place slot scoring after group stage:** for each of the 8 R32 third-place slots, user gets 1 pt if their predicted team matches the team FIFA actually places there. Test partial-correct cases (3 of 8 right), all-correct, all-wrong, and the case where the user picked a team from a group whose 3rd-place didn't advance.
- **Long username / emoji / bidi unicode:** username validator handles or rejects gracefully.

## Critical Paths (must work end-to-end before opening night)

1. **Sign-in → first prediction → leaderboard appears** — full onboarding flow for a brand-new family member.
2. **Predict full bracket in one session, log out, log back in, predictions persist.**
3. **Round lock enforcement** — pre-deadline edits land, post-deadline edits are blocked with a clear message.
4. **Match finishes → cron polls api-football → scoring runs → leaderboard updates** — the full reality loop. Test with a real api-football response (use a recent friendly match) before deployment.
5. **Mobile responsive bracket flow** — the family will mostly be on phones.

## Pure-function unit test coverage (Vitest)

100% coverage on `lib/bracket.ts`. Every branch of every function. Specifically:

- `computeGroupStandings(predictions)` — 8 branches (happy path, each tiebreaker step, empty input, partial input).
- `populateR32Slots(standings, thirdPlacePicks)` — 4 branches (happy, FIFA structure correctness, dropdown collisions, missing third-place pick).
- `computeMatchPoints(prediction, actualMatch)` — 8 branches (group exact, group outcome-only, group wrong, knockout score handling for penalties, knockout outcome rejects ties, withdrawn match, status not finished, partial credit edge cases).
- `computeFinalistPoints(picks, finalStandings)` — 4 branches (all correct, champion only, second only, all wrong).
- `computeThirdPlacePlacementPoints(predictedAssignments, realR32Slots)` — 5 branches: all 8 correct (8 pts), all wrong (0 pts), partial (e.g. 3 of 8), user picked team from a group whose 3rd-place didn't advance (0 pts that slot), R32 slots not yet populated (returns null, no scoring yet).
- `computeLeaderboard(predictions, finalistPicks, thirdPlaceAssignments)` — 3 branches (happy path, full tiebreaker chain, all-zeros pre-tournament).
